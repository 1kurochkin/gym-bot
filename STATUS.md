## Известные проблемы / вопросы к владельцу
- 2026-10-01, инцидент после деплоя i18n и приглашений: ответы с задержкой до 10 минут. Причины: функция запускалась у Telegram (Европа/us-east-1) далеко от БД (us-east-2) — ~150–200 мс на запрос; параллельные запросы загрузки уходили пачкой по одному соединению через Supavisor, и пулер терял ответ — апдейт висел до таймаута grammY (10 с), Telegram повторял. Исправлено: регион webhook, запросы по одному, апдейты воркера по очереди (docs/architecture.md §3). В логах — строка времени этапов на апдейт.
- Токен бота попал в логи Supabase (BotError grammY с контекстом) до исправления — нужно перевыпустить в @BotFather и обновить `.env.prod`, `.env`, GitHub Secret `BOT_TOKEN`, затем `prod.sh secrets` и `webhook:set`. Теперь ошибки пишутся без контекста.
- Импорт src/ вне supabase/functions/ работает и в `functions serve`, и в облачном `functions deploy --use-api` (проверено 2026-09-30).
- Edge runtime локально — supabase-edge-runtime 1.76 (совместим с Deno 2.1.4), а тулчейн — Deno 2.9: новые API Deno использовать осторожно, проверять через `supabase functions serve`.
- Если отправка ответа в Telegram упала после записи в БД, webhook вернёт 500, а ретрай Telegram будет проигнорирован по update_id: ответ пользователю потеряется, данные — нет.
