# ADR-0006: Архитектура кода — functional core / imperative shell, диалог как автомат, срезы по фичам, Deno

Статус: accepted
Дата: 2026-09-28

## Контекст
Почти вся ценность бота — в чистой логике (разминка, блины, ротация, 100/70, переходы диалога),
ввод-вывод тонкий. Функция stateless, живёт один запрос. Код будут писать и править агенты,
поэтому границы должны проверяться автоматически.

## Решение
- Ядро — чистые функции без I/O и без чтения текущего времени; размеченные объединения, результат
  с типизированной ошибкой вместо исключений, неизменяемые данные, без классов.
- Диалог — чистый конечный автомат: (состояние, событие, контекст) → (новое состояние, эффекты);
  состояние хранится в БД.
- Слои: ядро, порты (интерфейсы внешнего мира), срезы по фичам, адаптеры (реализации портов),
  composition root. Правило зависимостей между слоями проверяется автоматическим тестом.
- Тулчейн — Deno везде (тесты, линтер, форматтер, typecheck); npm-пакеты через `npm:`.
Подробно — архитектурный гайд, §13.

## Альтернативы
- Плагин conversations из grammY — в serverless переигрывает историю, сложно отлаживать.
- XState — лишний вес и абстракция для автомата из десятка состояний.
- Node-тулчейн (vitest, ESLint) — два рантайма, класс ошибок «в тестах работает, в функции нет».
- Слои по техническому типу (handlers/, services/) — фича размазывается по папкам.

## Последствия
Сценарии приёмки тестируются как последовательности событий без Telegram. Новая фича — новый срез, ядро не трогается.
Проверено на этапе 0: grammY, Drizzle, postgres и drizzle-kit работают под Deno 2.9.
