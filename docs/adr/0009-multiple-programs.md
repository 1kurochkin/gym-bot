# ADR-0009: Несколько программ в работе одновременно, текущая — последняя выбранная

Статус: proposed
Дата: 2026-10-12

## Контекст
Владелец хочет тренироваться по двум программам параллельно, без архивации первой: по умолчанию
бот берёт программу прошлой тренировки, но можно выбрать другую из списка. Сейчас активна ровно
одна программа: новая архивирует старую. Три места молча полагаются на это:
- «прошлый раз» ищется по id упражнения среди всех записей пользователя, без учёта программы;
- «следующий день» считается от последней тренировки, какой бы программы она ни была;
- переопределения шага веса в настройках привязаны к id упражнения.
Программы из редактора и из текста получают id упражнений `ex_1`, `ex_2` … и один id программы
`custom`, поэтому у двух таких программ совпадут и упражнения, и сама программа (вторая
сохранится как версия первой).

## Решение
- **Статус «в работе».** У программы три состояния: в работе (`active`), в архиве (`archived`),
  и у одной из программ в работе — отметка «текущая» (указатель в настройках, как сейчас).
  В работе может быть несколько программ. Архивирует только явное действие пользователя.
- **Текущая программа** — та, по которой была последняя начатая тренировка или которую
  пользователь выбрал последней. `/workout`, `/program`, `/seed`, редактор и шаг веса работают с
  текущей. Пока идёт тренировка, текущую сменить нельзя.
- **Выбор.** Если программ в работе больше одной: в `/workout` над выбором дня — «Программа:
  «…»» и кнопка [🔄 Другая программа] → список программ в работе → выбор делает её текущей и
  сразу показывает её дни. Та же кнопка — на экране `/program`, рядом [🗄 В архив] (не для
  программы с идущей тренировкой). Одна программа — экраны как сейчас.
- **Новая программа при существующей** (файл, «Составить программу», «Программа из текста»):
  [➕ Добавить к программам] [♻️ Заменить текущую] [Отмена]. «Заменить» — как сейчас, с архивом
  текущей; «Добавить» — новая программа в работе и сразу текущая. Файл с тем же `id`, что у
  программы в работе, — новая версия этой программы, без вопроса.
- **Уникальный id программы.** Программы из редактора и LLM получают первый свободный у
  пользователя `custom`, `custom_2`, `custom_3` …
- **История по программе.** «Прошлый раз», «следующий день» и переопределения шага считаются в
  пределах программы (по её `id` — то есть через все версии), а не по всему пользователю.
  Схема БД не меняется: записи уже ссылаются на версию программы, а версия — на её `id`;
  переопределения шага получают ключ «программа + упражнение», старые ключи читаются как
  относящиеся к текущей программе.

## Альтернативы
- Одна активная программа и быстрая замена туда-обратно — архив и разархивация на каждой
  тренировке, «прошлый раз» всё равно путается между программами с одинаковыми id.
- История по названию упражнения, а не по программе — «Присед» в двух программах получил бы
  общий «прошлый раз», но названия правят, а одинаковое название не значит одинаковую схему.
  Перенос веса между программами закрывает `/seed`.
- Глобально уникальные id упражнений у пользователя — ломает загрузку JSON (id задаёт автор
  программы) и не решает «следующий день».

## Последствия
- Миграций схемы нет; меняются запросы «прошлый раз», «последняя тренировка» и чтение
  переопределений шага. Существующие данные остаются как есть: у владельца сейчас одна
  программа в работе, поведение для него не меняется, пока он не добавит вторую.
- Владелец, перешедший с одной программы на другую заменой, «прошлый раз» из старой программы в
  новой больше не увидит, если `id` программ разные (сейчас видит при совпадающих id
  упражнений). Для такого перехода — `/seed`.
- Новый вопрос при загрузке программы и новые экраны выбора — спека (US-1, US-2), тексты ru/en,
  тесты сценариев.
- `/history` при нескольких программах показывает название программы у тренировки.
