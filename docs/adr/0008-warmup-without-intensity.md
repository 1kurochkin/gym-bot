# ADR-0008: Разминка ступенями от рабочего веса без привязки к 100/70

Статус: accepted
Дата: 2026-10-12

## Контекст
ADR-0003 связал перегрузочный сингл с чередованием интенсивности: «не в дни на 70%». Чередование
100/70 убрано решением владельца 08.10: бот больше не знает, лёгкий ли сегодня день, а флаг
`skipOnLowIntensity` в программе допустим, но игнорируется. Условие в ADR-0003 устарело, а сам
ADR — снимок, его не правят. Остальная часть решения о разминке действует.

## Решение
- Ступени по рабочему весу (< 135 / 135–224 / ≥ 225 lb) с процентами из программы
  (`warmupTiers`), округление к ближайшему собираемому весу (при равенстве — вниз).
- Перегрузочный сингл 105% — у каждого упражнения с `isBase: true`, в любой день; если
  округлённый вес не выше рабочего, сингл поднимается до следующего собираемого веса.
- Для упражнений с допвесом — отдельная таблица от допвеса (свой вес, ступени, сингл 110% от
  25 lb допвеса).
- Упражнение с фиксированной схемой разминки использует её вместо ступеней.
Детали и контрольные примеры — в спецификации разминки (§6.2–6.3); примеры покрыты тестами.

## Альтернативы
- Оставить ADR-0003 с пометкой в тексте — нарушает правило «ADR не правят» и прячет изменение.
- Убрать сингл вместе с 100/70 — сингл не зависел от чередования по сути, он готовит к рабочему
  весу базового упражнения; владелец его не отменял.

## Последствия
- ADR-0003 — `superseded by ADR-0008`.
- Упражнения, созданные кнопками редактора или из текста через LLM, получают `isBase: false`,
  то есть без сингла; сингл включается только флагом `isBase` в JSON программы.
- Поля чередования в программе (`intensityPairs`, `intensityGroup`, `skipOnLowIntensity`)
  по-прежнему допустимы и игнорируются, старые программы загружаются без правок.
