# Харнесс для агентов

## 12. Репозиторий и харнесс для агентов

Цель: любая новая сессия агента (без памяти о прошлых чатах) за пару минут понимает, что это за проект, где правила и что делать дальше. Принцип — минимум структуры, которая реально читается и обновляется; ничего не создаётся «на вырост».

| Где | Что | Кто обновляет |
|---|---|---|
| `CLAUDE.md` | Входная точка: продукт в 2–3 предложениях, карта папок, команды, правила, Definition of Done (≤ 150 строк) | При изменении правил или структуры |
| `STATUS.md` | Текущий этап, чеклист, последние решения, следующий шаг, известные проблемы | В конце каждой сессии |
| `.specs/` | Что делает бот: спецификации по темам с индексом | До кода, в том же коммите |
| `docs/` | Как устроен код: архитектурный гайд, этот документ, ADR, runbook'и; свой индекс | При изменении принципов |
| `tests/fixtures/` | Контрольные примеры из спецификаций как данные | Вместе со спекой |
| `.claude/` | Хуки и скиллы Claude Code | При изменении процесса |

**Правила, зафиксированные в `CLAUDE.md`:** спецификация — источник истины (сначала `.specs/`, потом код); дорогое для отката решение → новый ADR; пример в спеке без фикстуры — баг; ядро без I/O; все веса в lb, даты в UTC плюс локальная дата; в конце сессии обновить `STATUS.md`.

### 12.1. Что писать в документах

Устаревший документ для агента хуже отсутствующего: агент доверяет тексту и идёт туда, куда он указывает. Код агент находит поиском за секунды, поэтому документы отвечают на то, чего в коде нет: **зачем**, **какие инварианты**, **какие границы**. Правило, которое можно проверить машиной, проверяется тестом, а документ объясняет его смысл.

| Документ | Пишем | Ссылки на код |
|---|---|---|
| ADR | Контекст, решение, альтернативы, последствия — идеей | Нет. ADR — снимок на момент решения: его не правят, а заменяют новым ADR (`superseded by`) |
| Архитектурный гайд | Принципы, инварианты, слои, 1–2 примера с пометкой «иллюстрация» | Только до уровня слоя (`src/core/` …) и инфраструктурные папки. Без имён функций, типов, полных деревьев файлов |
| `CLAUDE.md` | Карта папок, команды, правила | Только то, что существует сейчас; ничего запланированного |
| Спецификации | Поведение: числа, сценарии, контрольные примеры | Нет. Связь «спека → код» держат фикстуры и тесты |
| `STATUS.md`, runbook'и | Как есть: состояние, шаги | Можно — они операционные и переписываются по ходу |

**Проверка ссылок.** Тест в `deno task check` находит в `.md` пути к файлам репозитория и падает, если файла нет. Переименовал файл — поправь документ в том же коммите.

### 12.2. `STATUS.md` и ADR

`STATUS.md` — самый полезный файл для длинного проекта: при сбросе контекста агент читает его первым и продолжает с того же места. Формат задан самим файлом.

ADR — не оверинжиниринг, если держать их короткими (полстраницы). Они отвечают на вопрос «почему так», который из кода не восстановить (почему Supabase, а не Cloudflare; почему IANA-зона, а не UTC−4). Статусы: `proposed` / `accepted` / `superseded by 000X`. Шаблон и список — в `docs/adr/`.

### 12.3. Хуки (2 штуки, не больше)

- **После правки `.ts`** — быстрый typecheck и lint изменённого файла. Ошибка возвращается агенту сразу, а не в конце.
- **Перед завершением работы (`Stop`)** — полный `deno task check`. Агент не закончит работу с красными тестами; защита от зацикливания, если агент уже чинит ошибки по сигналу хука.

Если typecheck всего проекта на каждую правку станет медленным, в первом хуке оставить только lint, а typecheck перенести в `Stop`. Для хуков нужен `jq`.

### 12.4. Skills и MCP

**`/deploy`** — деплой в прод: логин в Supabase CLI, `.env.prod`, секреты, миграции, функция, webhook. Значения секретов скилл не читает и не выводит: с `.env.prod` работает только его вспомогательный скрипт, который печатает имена переменных, а не значения.

Остальные skills и MCP заводятся, когда задача повторится второй раз, а не заранее. Кандидаты: skill «добавить новый тип упражнения или схему разминки» (спека → фикстуры → ядро → фича → экспорт); официальный MCP-сервер Supabase, если отладка через SQL-редактор станет утомительной.
