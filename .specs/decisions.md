# Решения

## 11. Решения и открытые вопросы

**Принято (22.09)**

- Блины 2,5 lb появятся позже: добавляются в `/settings`, всё пересчитывается само (6.2).
- Разминка строится ступенями от рабочего веса, а не от упражнения (6.2).
- Перегрузочный сингл — только в базовых упражнениях (`isBase`) и не в дни на 70%.
- Шаг веса настраивается по упражнению в `/settings`, чтобы смена тренажёра не требовала правки программы (раздел 4).
- Шея ведётся по весу блина с шагом 2,5 lb.
- Вес тела не отслеживается.
- Часовой пояс спрашивается при онбординге, хранится IANA-зона, показывается как `UTC−4 · New York` (раздел 7).
- 28.09: хостинг и БД — Supabase (Edge Functions + Postgres), защита от засыпания и бэкапы через GitHub Actions (раздел 3, ADR-0001).
- 28.09: бэкапы — ежедневный дамп БД файлом в личный чат Telegram (не в публичный GitHub) и схема в миграциях; автоматической еженедельной выгрузки `.xlsx` нет, только `/export`.
- 28.09: подтверждены ступени разминки от рабочего веса (6.2) и таблица для брусьев и подтягиваний (6.3).
- 28.09: архитектура кода — functional core / imperative shell, диалог как чистый конечный автомат, структура по фичам с правилом зависимостей, тулчейн Deno (раздел 13, ADR-0006).
- 28.09: часовой пояс при онбординге — по текущему времени пользователя (кнопки зон с этим смещением) или по геопозиции; ввод города убран (.specs/data-model.md → Часовой пояс).
- 30.09: время отдыха вне скоупа: бот его не считает и не показывает; поля `restSec` и `restBeforeWorkSec` убраны из формата программы (пример экрана разминки противоречил формуле линейного отдыха).
- 30.09: ввод подхода с учётом контекста: одно число — повторения с предложенным ботом весом; вес и повторения — свой вес (product.md → «Ввод свободным текстом»).
- 30.09: чередование 100/70 смотрит последнюю неделю, в которую пара выполнялась, а не строго прошлую: пропуск недели не сбивает чередование (§6.4).
- 30.09: программа загружается в основном файлом `.json`: отформатированная программа владельца больше лимита сообщения Telegram (4096). Замена активной программы — только после подтверждения кнопкой.
- 30.09: стартовые результаты (`/seed`) — записи `manual_import` без тренировки: `workoutId` у них пуст. «Прошлый раз» — лучший рабочий подход последней записи упражнения.
- 30.09: `/settings` — экран разделов; шаг по упражнениям — только для упражнений не на штанге (у штанги шаг задают блины).
- 01.10: бот может быть у нескольких знакомых владельца (доступ по списку), поэтому интерфейс на русском и английском. Язык — из `/settings`, по умолчанию по языку Telegram; у существующих пользователей при миграции проставлен русский. Тексты программы не переводятся (product.md → «Язык интерфейса»).
- 01.10: новые пользователи — по одноразовой ссылке-приглашению от владельца (`/invite`), а не через конфигурацию; владельцы остаются в `ALLOWED_USER_IDS`. Запрос доступа от незнакомцев отвергнут: бот для чужих должен молчать (product.md → US-9).
- 01.10: «Назад» — только до первого рабочего подхода (разминка → вес, шаг отметки разминки → предыдущий, первый подход → разминка); после записи рабочего подхода — `/undo` и [✏️ Исправить], они удаляют последний подход и возвращают к его вводу.
- 02.10: кнопки с текстом — списком (по одной в строку), числовые — сеткой; `/clear` — удаление переписки за 48 часов (ограничение Telegram), данные не трогаются.
- 02.10: тренировка — меню дня (product.md → US-2…US-4): упражнения выбираются в меню, подходы идут до «Завершить упражнение», после подхода экрана «Записал …» нет; «Заменить», «Другое упражнение», «Пропустить упражнение», вопрос «Продолжить тренировку?» убраны — их заменяют меню и «Добавить упражнение». «Назад» ничего не удаляет: с ввода подхода — просмотр прошлого подхода с [✏️ Изменить] [🗑 Удалить]. Кнопки повторений — 8 подряд. По опыту владельца в зале.
- 02.10 (заменено меню дня в тот же день): [← Назад] на каждом экране тренировки — «отменить последнее действие и вернуться на предыдущий экран»; [✏️ Исправить] слит с «Назад» (делали одно и то же). [⏭ Пропустить] на каждом подходе: после первого — закончить упражнение досрочно. Название упражнения — жирным на всех его экранах (product.md → US-3, US-4).
- 01.10: на нажатие кнопки бот отвечает Telegram (`answerCallbackQuery`) после обработки, а не до: пока бот работает, на кнопке виден индикатор загрузки. Защита от двойного нажатия — по-прежнему номер шага в кнопке.
- 01.10: замена упражнения — только из упражнений программы (своё название — позже); запись замены — `done` с `substitutedFor`. Порядок упражнений свободный: следующим всегда идёт первое невыполненное по порядку дня.
- 01.10: `/history` — правка прошлых тренировок: рабочие подходы (исправить, добавить, удалить) и удаление тренировки целиком; разминка и комментарии не редактируются; текущая тренировка — только через `/undo`.
- 01.10: кнопка [➖ Короче] (§6.5) отложена в фазу 2; доп. подход своим весом после брусьев и подтягиваний (`afterWork`, §6.3) — вне скоупа: бот считает разминку и запоминает рабочий вес, а не советует по программе. Поле `afterWork` в формате программы остаётся допустимым, бот его не использует. Кнопки «Отметить отличия»: [✅ Готово] [✏️ Изменить] [⏭ Пропустить].
- 08.10: чередование 100/70 убрано (решение владельца): нет вопроса «что на 100%», кнопки «Сделать 70%», веса на 70% и метки `intensity` в новых записях; вес по умолчанию — прошлый раз. `intensityPairs`, `intensityGroup`, `skipOnLowIntensity` в программе допустимы и игнорируются; `conditionalNotes` показываются всегда; старые записи сохраняют метку (§6.4).

**Открыто**

Открытых вопросов нет, спецификация готова к передаче агенту.
