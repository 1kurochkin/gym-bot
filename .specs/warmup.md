# Алгоритмы

## 6. Алгоритмы

Все алгоритмы этого раздела — чистые функции ядра, без LLM, со 100% покрытием unit-тестами.

### 6.1. Собираемые веса штанги

Настройки по умолчанию: гриф 45 lb, блины 5, 10, 25, 35, 45 lb (количество не ограничено). Любое кратное 5 на сторону собирается, поэтому доступные веса: `45 + 10·k`. Шаг штанги = 10 lb.

Общий алгоритм (на случай, если набор блинов в настройках изменится): перебрать суммы на одну сторону, достижимые из списка блинов, до 400 lb на сторону, получить отсортированный массив собираемых весов `bar + 2·side`. Раскладку по блинам бот не показывает, только вес на сторону: «205 (по 80)».

### 6.2. Разминка ступенями от рабочего веса (штанга, тренажёры)

Количество разминочных подходов зависит не от упражнения, а от рабочего веса: чем тяжелее, тем больше ступеней. Пороги и проценты задаются в программе (`warmupTiers`) и имеют значения по умолчанию:

| Рабочий вес W | Разминочные подходы | + перегрузочный сингл |
|---|---|---|
| < 135 lb (~60 кг) | 50%×8 · 80%×3 | 105%×1 |
| 135–224 lb (~60–100 кг) | 45%×8 · 70%×5 · 85%×3 | 105%×1 |
| ≥ 225 lb (~100 кг+) | 40%×10 · 60%×8 · 75%×5 · 90%×3 | 105%×1 |

Перегрузочный сингл добавляется только для упражнений с `isBase: true` и не добавляется в дни на 70%. Упражнение с фиксированной схемой (например, икры 50%×10 · 80%×10) использует её вместо ступеней.

Алгоритм для рабочего веса `W`:

1. Выбрать ступень по `W` (для дня на 70% — по уже уменьшенному весу).
2. Для каждого шага `target = W · pct`, округлить до ближайшего собираемого веса (для `barbell`) или до шага упражнения (для `machine`). При равенстве округлять вниз.
3. Нижний предел для штанги — вес грифа («пустой гриф»).
4. Шаги с `pct < 1`: если округлённый вес ≥ `W`, шаг выбрасывается.
5. Перегрузочный сингл: если округлённый вес ≤ `W`, он поднимается до следующего собираемого веса выше `W`.
6. Дубликаты схлопываются, остаётся более ранний шаг.
7. Результат — строго возрастающий список `{weight, reps, restSec, label, perSide}`. Отдых растёт линейно от `restSec.first` до `restSec.beforeWork`.

**Контрольные примеры (обязательны в тестах, лежат в `tests/fixtures/`)**

| Блины | W | Ожидаемая разминка |
|---|---|---|
| 5–45 | 95 | 45×8 (пустой) · 75×3 (по 15) · 105×1 (по 30) |
| 5–45 | 195 | 85×8 (по 20) · 135×5 (по 45) · 165×3 (по 60) · 205×1 (по 80) |
| 5–45 | 225 | 85×10 (по 20) · 135×8 (по 45) · 165×5 (по 60) · 205×3 (по 80) · 235×1 (по 95) |
| 5–45 | 315 | 125×10 (по 40) · 185×8 (по 70) · 235×5 (по 95) · 285×3 (по 120) · 335×1 (по 145) |
| 2,5–45 | 195 | 90×8 (по 22,5) · 135×5 (по 45) · 165×3 (по 60) · 205×1 (по 80) |
| 5–45, день 70% | 225 → 155 | 65×8 (по 10) · 105×5 (по 30) · 135×3 (по 45) (ступень 135–224, без сингла) |

Если `W` сам не собирается (например, 190 без блинов 2,5), бот принимает его, но предупреждает: «190 не собрать, ближайшие: 185 / 195».

**Блины 2,5 lb.** Сейчас их нет, владелец собирается купить. После добавления в `/settings` шаг штанги станет 5 lb, и все расчёты (разминка, кнопки ±, вес на 70%) пересчитаются автоматически.

### 6.3. Разминка для брусьев и подтягиваний

Здесь рабочий «вес» = допвес `A` на поясе (0 = свой вес). Тот же принцип ступеней, только первая ступень всегда свой вес, а проценты берутся от допвеса:

| Допвес A | Разминка | После рабочего |
|---|---|---|
| 0 | Блок/резина ×10–12 | Второй рабочий со своим весом через 4 мин |
| < 25 lb (~10 кг) | Свой вес ×8 · 80%×4 | Доп. подход со своим весом на максимум через 4 мин |
| 25–59 lb | Свой вес ×10 · 50%×5 · 85%×3 · сингл 110%×1 | — |
| ≥ 60 lb (~27 кг+) | Свой вес ×10 · 40%×6 · 75%×4 · сингл 110%×1 | — |

Это обобщение двух примеров из программы (+10 кг и +40 кг). Округление до шага (5 lb, после покупки блинов — 2,5 lb).

Примеры: `A = 90` → свой×10 · +35×6 · +65×4 · +100×1 → рабочий +90. `A = 40` → свой×10 · +20×5 · +35×3 · +45×1 → рабочий +40. `A = 15` → свой×8 · +10×4 → рабочий +15 → свой вес на максимум.

### 6.4. Чередование 100% / 70%

Для пары из `intensityPairs` с `mode: alternate_weekly`. Неделя = ISO-неделя (пн–вс).

1. Если одно упражнение пары уже выполнено на этой неделе, второе получает противоположную интенсивность.
2. Иначе смотрим прошлую неделю: упражнение, которое было на 100%, теперь идёт на 70%.
3. Если истории нет — бот спрашивает, какое упражнение ведущее на этой неделе.
4. Пользователь всегда может переключить интенсивность кнопкой. Выбор записывается в лог (`intensity: high | low`).
5. Вес по умолчанию для 70%: `round(0.7 · последний рабочий вес с intensity = high)` до собираемого.
6. В карточке показываются оба прошлых результата: «Прошлый 100%: 225×7 (08.09) · прошлый 70%: 155×8 (15.09)».
7. `conditionalNotes`: заметка к тяге в наклоне показывается, если становая на этой неделе `high` (выполнена или запланирована по правилам 1–2).

Для дней с 70% перегрузочный сингл в разминке не нужен: шаги с `pct > 1` пропускаются.

### 6.5. Корректировка разминки

На экране разминки бот показывает комментарий к разминке с прошлого раза, если он был («💬 прошлый раз: устал после разминки»). Кнопка [➖ Короче] строит разминку по ступени на уровень ниже (для самой нижней — убирает первый шаг). Выбранный вариант пишется в лог (`warmupVariant: full | short | custom | none`), чтобы потом сравнить, какая разминка даёт лучший рабочий подход.

Фаза 2: LLM по прошлым комментариям предлагает вариант (не применяет сам).
