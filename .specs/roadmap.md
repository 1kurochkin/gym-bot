# Roadmap

## 10. Этапы и критерии приёмки

### Этап 0. Каркас (≈ 0,5 дня)

- [x] Харнесс репозитория по разделу 12: `CLAUDE.md`, `.specs/`, `docs/adr/` (ADR-0001…0005), `STATUS.md`, хуки.
- [x] Проект Supabase (Edge Function `bot` на Deno + grammY, Postgres + Drizzle, `verify_jwt = false`), каркас папок и правило зависимостей из раздела 13, `deno task dev` (локальный Supabase + long polling) и `deno task check`; GitHub Actions `ci.yml` и `backup.yml`.
- [x] Whitelist, секреты, webhook с секретным токеном, онбординг часового пояса.

- **Готово, когда:** бот отвечает на `/start` только владельцу локально и после деплоя; `deno task check` зелёный, включая architecture test; агент в новой сессии по одному `CLAUDE.md` находит, где лежит спецификация разминки.

### Этап 1. Домен (≈ 1 день)

- [ ] zod-схема программы, валидация программы из раздела 4.
- [ ] Собираемые веса, разминки обоих типов, ротация, чередование, парсер ввода.

- **Готово, когда:** все контрольные примеры раздела 6 проходят в тестах; JSON программы из раздела 4 валиден.

### Этап 2. Программа и стартовые веса (≈ 1 день)

- [ ] `/program` (файл и текст), архивирование старой, сводка.
- [ ] `/seed` пошагово, `/settings`.

- **Готово, когда:** загрузка программы с ошибкой показывает понятный список ошибок; после `/seed` в карточке упражнения виден «Прошлый раз».

### Этап 3. Тренировочный флоу (≈ 2–3 дня)

- [ ] Выбор дня с подсказкой прошлой тренировки и выделением следующего.
- [ ] Карточка упражнения, выбор веса, разминка, рабочие подходы, комментарии.
- [ ] Все `loadType`, чередование 100/70, условные заметки.
- [ ] Пропуск, замена, другой порядок, `/undo`, возобновление и `/cancel`.
- [ ] Сводка в конце.

- **Готово, когда** (сквозной сценарий в эмуляторе):
    1. Пятница прошлой недели завершена → `/workout` показывает «Прошлая тренировка: … Подтягивания + тяга» и первым предлагает «Фронтальный присед».
    2. Выбор 195 для жима даёт ровно разминку из таблицы 6.2.
    3. Закрыть Telegram посреди упражнения, открыть снова → бот предлагает продолжить с того же шага, ничего не потеряно.
    4. Двойное нажатие на кнопку повторений создаёт один подход, а не два.
    5. Если присед на этой неделе шёл на 100%, для становой по умолчанию предлагается 70% от последнего 100%-веса.
    6. Среднее время на ввод одного рабочего подхода — ≤ 3 нажатия.

### Этап 4. Экспорт (≈ 1 день)

- [ ] `/export` со всеми листами раздела 8.

- **Готово, когда:** файл открывается в Excel и Google Sheets без ошибок; числа — числами; в `sets` ровно столько строк, сколько записано подходов, включая разминочные; отдав файл LLM, можно получить ответ «как менялся e1RM жима по неделям» без дополнительных пояснений.

### Этап 5 (фаза 2). LLM и Google Sheets

- [ ] Импорт истории одним сообщением с подтверждением.
- [ ] Разбор свободного текста в тренировке.
- [ ] Конвертер программы из текста в JSON.
- [ ] Зеркало в Google Sheets.
- [ ] Предложение варианта разминки по прошлым комментариям.

- **Готово, когда:** сообщение «жим 185 на 9 последний тяжело, присед 205х7, брусья +25 на 8» распознаётся в три записи с комментарием у жима, и в базу ничего не пишется до нажатия «Сохранить».
